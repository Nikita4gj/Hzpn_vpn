# HZPN - **H**ardened **Z**ero-trust **P**ersonal **N**etwork

Учебная реализация VPN, работающего на сетевом уровне (L3): весь IP-трафик клиента перехватывается через TUN-интерфейс, инкапсулируется и передаётся на сервер, который распаковывает пакеты и выпускает их в сеть от своего имени.

Это не HTTP/SOCKS-прокси прикладного уровня — туннелируется любой IP-трафик независимо от протокола поверх него.

> **Статус:** ранняя разработка. Рабочей сборки пока нет.

## Как это устроено

```
[приложение] → [tun0] → [hzpn_client] → сеть → [hzpn_server] → [tun0] → интернет
```

1. Клиент создаёт виртуальный интерфейс `tun0` и прописывает маршруты так, чтобы трафик уходил в него.
2. Ядро отдаёт клиенту сырые IP-пакеты через файловый дескриптор TUN.
3. Клиент оборачивает пакет в кадр собственного протокола и отправляет серверу.
4. Сервер извлекает пакет, отправляет его в реальную сеть, ответ проделывает обратный путь.

## Компоненты

| Компонент    | Назначение                                                           |
| ------------ | -------------------------------------------------------------------- |
| `hzpn_client` | Создаёт TUN-интерфейс, настраивает маршруты, гоняет пакеты к серверу |
| `hzpn_server` | Принимает соединения, маршрутизирует трафик клиентов наружу, NAT     |
| `common`      | Формат кадра, сериализация, криптография, общие утилиты              |

## Требования

- Linux с поддержкой `/dev/net/tun`
- C++20, CMake 3.20+
- Компилятор GCC 12+ или Clang 15+

## Запуск

> TODO: появится вместе с первой рабочей версией.

Оба бинарника поднимают TUN-интерфейс и правят таблицу маршрутизации, поэтому требуют capability `CAP_NET_ADMIN`. Запуск из-под `sudo` работает, но выдаёт процессу заметно больше прав, чем нужно. Предпочтительный вариант — выдать capability конкретному бинарнику один раз после сборки:

```bash
sudo setcap cap_net_admin+ep build/hzpn_client
```
