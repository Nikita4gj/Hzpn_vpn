# План разработки

Каждый этап заканчивается проверкой, которую можно воспроизвести руками. Этап считается закрытым, когда проверка проходит у любого участника команды, а не только у автора.

## Этап 0. Инфраструктура

Текущая цель. Три независимые ветки, каждая уходит в `main` своим PR.

| Ветка                | Содержимое                                                                                                                                         | Готово, когда                                                                                           | Кто      реализует |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------ |
| `docs`               | ADR, план, роли, README                                                                                                                            | PR смержен                                                                                              | Все члены команды  |
| `feature/cmake-base` | Корневой `CMakeLists.txt`, `CMakePresets.json`, пустые таргеты `hzpn_client`, `hzpn_server`, библиотека `common`, подключение тестового фреймворка | `cmake --preset debug && cmake --build --preset debug && ctest --preset debug` проходит на чистом клоне | Явченко Никита     |
| `feature/ci`         | `.github/workflows/ci.yml`: сборка и тесты на каждый PR                                                                                            | Статус CI виден в PR и сломанная сборка блокирует мерж                                                  | Явченко Никита     |

Порядок: `feature/ci` зависит от `feature/cmake-base`, остальное параллельно.

## Этап 1. TUN

Клиент открывает TUN-интерфейс, читает пакеты и печатает их заголовки.

**Проверка:** `ping` на адрес из подсети интерфейса, в выводе программы видны
ICMP-пакеты.

## Этап 2. Туннель по локальной сети

Клиент и сервер обмениваются IP-пакетами поверх TCP без шифрования
([ADR 0001](adr/0001-transport.md)).

**До начала:** ADR на границу между TUN и транспортом — кто владеет циклом
событий и через какой интерфейс пакет переходит из одной части в другую.

**Проверка:** `ping` адреса сервера внутри туннеля с другой машины в локальной
сети; `tcpdump` на физическом интерфейсе показывает только TCP-соединение
туннеля.

## Этап 3. Выход в интернет

Сервер пересылает трафик клиентов наружу: `ip_forward`, NAT, маршрут по
умолчанию на клиенте через туннель.

**Проверка:** `curl ifconfig.me` на клиенте возвращает адрес сервера.

## Этап 4. Криптография и аутентификация

Шифрование канала и аутентификация клиента по ключу на основе libsodium.
Сервер не принимает трафик от клиента, не прошедшего рукопожатие.

**Проверка:** `tcpdump` показывает нечитаемую полезную нагрузку; клиент с
чужим ключом получает отказ.

## Этап 5. UDP

Второй транспорт и сравнительные замеры с TCP при искусственных потерях.

**Проверка:** таблица скорости обоих транспортов при `netem loss 0%, 1%, 5%`.

## Этап 6. Демон и несколько клиентов

Разделение привилегий: демон с `CAP_NET_ADMIN` и CLI без прав. Сервер
обслуживает несколько клиентов одновременно.

## Этап 7. Windows

Клиент под Windows через Wintun.
